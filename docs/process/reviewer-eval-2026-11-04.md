### 발견과 고친 것
1. **병합 규칙의 빈틈 (c4):** 규칙이 완료 조건만 보고, 이슈가 "범위 밖"이라고 **명시한** 것을 바꿔도 통과를 냈다 → 지시문: 그런 변경은 `[범위 위반]`, 미충족·**일부**·[범위 위반]이면 보류
2. **세트의 실수 (c2):** `app/report.py`의 `to_csv`가 이미 BOM을 붙여 조건 1의 정답이 모호했다. 리뷰어가 1차에서 이중 BOM을 찾았고(다음 실행에서는 못 찾음 — 실행마다 흔들림) → c2를 `Cache-Control: no-store` 사례로 다시 만듦
3. **심지 않은 결함:** c1의 import 순서(ruff I001), c4 시험의 `importlib.reload`(다른 시험이 쥔 모듈 상태를 바꿈) → 고침. 이제 결함 diff도 ruff·`tests/test_auth.py` 통과
4. **블라인드가 깨질 길:** 이 문서가 병합되면 저장소 안에 정답이 생긴다 → 리뷰어는 기준 커밋 worktree(`evals/`·이 문서 없음)를 읽게 바꿈
5. **결과를 보고 기대를 넓힘:** v1에서 c2·c4의 기대를 실행 뒤에 넓혔다 → v2는 실행 전에 고정하고, 고치기 전 점수(10/11)도 남김
