# 계약 리뷰어 평가 세트

`spec-reviewer`(계약 리뷰 서브에이전트)가 완료 조건을 빠뜨리거나 반만 구현한 변경을 잡아내는지 잰다.
https://github.com/reddol18/docflow/issues/24 "리뷰어 평가". **모델이나 지시문을 바꿀 때 같은 세트로 다시 돌려 비교한다.**

## 사례

| 사례 | 심은 결함 | 기대 |
|---|---|---|
| `c1` | 조건 3개 중 하나(`next_after`)를 빼먹음, 시험도 기본값만 | 미충족 1, 시험 일부 → 보류 |
| `c2` | 헤더(`Cache-Control: no-store`)만 넣고 시험 없음 | 시험 미충족 → 보류 |
| `c3` | 없음 (대조군) | 통과 — 거짓 경보를 잰다 |
| `c4` | 조건은 다 했지만 이슈가 범위 밖이라고 한 값(`MAX_FAILS`)을 슬쩍 바꿈 | 범위 밖에 적고 보류 |
| `c5` | 세 경우(`.`·`..`·`...`) 중 하나만 막음, 시험도 하나 | 일부·미충족 → 보류 |

각 폴더: `issue.md`(이슈 본문), `diff.patch`(기준 커밋에 적용하는 변경), `expected.yaml`(기대 판정).
- 기준 커밋: **`c0d8877`** (2026-11-04 main). diff는 여기서 `git apply --check`가 통과하고, ruff와 `tests/test_auth.py`도 통과한다 — 심은 결함 말고 다른 결함이 없게.
- 결함 사례에는 심은 결함 하나만 둔다. 사례를 고칠 때마다 위 확인을 다시 한다.
- `expected.yaml`은 **실행 전에 고정**한다. 실행 결과를 보고 넓히면 그 모델에 맞춘 점수가 된다 — 정말 기대가 틀렸으면 고치되, 고치기 전 점수도 함께 남긴다.

## 돌리는 법 (블라인드)

1. 기준 커밋을 저장소 밖에 따로 꺼낸다: `git worktree add --detach <임시폴더>\evalbase c0d8877`
   - 그 커밋에는 `evals/`와 결과 문서가 없다 → 리뷰어가 정답을 읽을 수 없다
2. 사례마다 `issue.md`와 `diff.patch`만 저장소 밖 임시 폴더로 복사한다
3. 사례마다 `spec-reviewer`를 따로 부른다. 지시: 이슈 본문 파일 경로, 비교 대상 = 그 diff.patch, 저장소 = 1의 폴더, gh 쓰지 말 것
4. 판정이 실행마다 흔들리므로 **사례당 2번 이상** 돌린다
5. 지시문 판을 남긴다: `~/.claude/agents/spec-reviewer.md`를 `reviewer/spec-reviewer-<sha256 앞 8자>.md`로 복사
6. 끝나면 `git worktree remove --force <임시폴더>\evalbase`

## 채점 (실행마다)

- **잡음:** 결함 사례(c1·c2·c4·c5)에서
  - c1·c2·c5: 해당 조건이 기대 판정 목록 안이고, 병합 판단이 **보류**
  - c4: 범위 밖 변경에 `MAX_FAILS`를 적고, 병합 판단이 **보류**
- **거짓 경보:** 대조군 c3을 보류·근거 보강으로 막았나
- **조건별 일치:** 모든 조건 중 기대 판정 목록 안에 든 비율 (참고값)

결과는 `docs/process/reviewer-eval-YYYY-MM-DD.md`에 모델·지시문 판(해시)과 함께 남긴다.
